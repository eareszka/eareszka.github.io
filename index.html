Selected projects

WingIt!

Cross-platform AI texting assistant · web, iOS & Android from one codebase

Reads a conversation screenshot, works out who said what, and drafts a reply matched to the other person's tone. A built-in coach answers questions about a specific conversation, and “The Read” gives an assessment of how both sides are coming across.

The hard part: a language model returns something fluent and wrong with exactly the confidence it returns something good. Most of the work was narrowing prompts until responses came back in a shape the interface could rely on, and deciding what the user sees when they don't. Screenshots are discarded after processing — which also means no saved corpus to re-test a prompt change against.

RegionOS

Windows live-preview desktop dashboard · v0.1.0 released July 2026

Draw regions anywhere on screen and each one keeps updating in real time — screen areas, application windows, or websites — even while the source is covered, minimized, or hidden off-screen. Fullscreen mode strips everything down to a grid of live previews.

The hard part: there is no image to copy off a window that isn't being drawn, so nearly everything structural in the codebase exists to solve that one clause. I kept it fully offline on deterministic computer vision rather than a model — it caps what the tool can do, and buys failures that repeat identically instead of a guess.

  • Win32 API
  • Computer vision

Pulse

Real-time multi-market anomaly dashboard · live since January 2026

Pulls equities, Polymarket prediction markets, and sports betting lines onto one screen and flags what is moving in a way the other sources don't confirm.

SnipAI

Chrome extension · AI screen-reader for a region of your tab

Watches any region of a browser tab and re-queries a vision model — Claude, GPT, or Gemini, switchable at runtime — the moment the pixels in that region change, behind one provider-agnostic interface sitting in front of three different vision APIs.

The hard part: Manifest V3 replaces the long-lived background page with a service worker that gets torn down, so watching a region, detecting the change, and calling the model all have to survive being restarted mid-task.

Campus Event Management System

Full-stack Django application · team build, Agile sprints

Internal event platform with authentication and role-based access: registration, waitlists, and attendance tracking. Built across separate frontend and backend teams on sprint cycles, with my work on registration and waitlists.

The hard part: a waitlist looks like a feature and is really an ordering problem. Store each person's position as a number and every read is cheap, but one cancellation in the middle means rewriting every row underneath it. Role-based access pushed on the same rows from the other side — an organizer and a student look at one registration and are entitled to different parts of it.
